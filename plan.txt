# Project: Multi-SMTP Email Management System

Act as a Senior PHP Developer, SaaS Product Architect, Database Engineer and UI/UX Designer.

Build a professional, responsive, self-hosted Multi-SMTP Email Management Dashboard using PHP, SQLite, HTML5, CSS3 and modern JavaScript.

The application should have a premium SaaS-style interface, secure authentication, SMTP account management, campaign management, email queues, delivery monitoring and detailed analytics.

## 1. Technology Stack

Backend:
- PHP 8.2+
- SQLite 3 with PDO
- Composer for PHP dependencies
- PHPMailer for SMTP transport
- PHP Sessions for authentication
- REST-style PHP API endpoints

Frontend:
- HTML5
- CSS3
- Vanilla JavaScript ES6+
- Bootstrap 5.3
- Bootstrap Icons
- Chart.js for analytics
- DataTables for server management tables
- SweetAlert2 for confirmation dialogs
- Toastify.js for notifications
- Flatpickr for date/time selection
- CodeMirror for HTML email template editing
- Quill.js for rich-text email editor
- SortableJS for drag-and-drop organization

Use CDN libraries where appropriate and provide local asset fallback options.

## 4. SMTP Account Management

Create an advanced SMTP management interface.

Features:
- Add SMTP account
- Edit SMTP account
- Delete SMTP account
- Enable/disable account
- Test SMTP connection
- Verify TLS/SSL configuration
- SMTP connection status
- Daily sending quota
- Hourly sending quota
- Sent count
- Failed count
- Last connection test
- Provider name

SMTP fields:
- SMTP Host
- SMTP Port
- Encryption (SSL/TLS/STARTTLS/None)
- Username
- Password
- From Email

- Hourly Limit

SMTP credentials must be encrypted at rest. Never expose SMTP passwords in API responses or logs.

## 5. SMTP Routing Engine

Create a configurable SMTP routing module.

Supported routing strategies:
- Round Robin
- Weighted Distribution
- Least Used
- Priority Based
- Manual SMTP Selection

Requirements:
- Respect provider-defined sending quotas.
- Never exceed account-level hourly or daily limits.
- Respect recipient consent and suppression lists.
- Prevent duplicate message dispatch.
- Handle SMTP connection failures.
- Retry temporary failures using exponential backoff.
- Do not retry permanent delivery errors.
- Record the SMTP account used for every message.

## 8. Email Queue

Build a dedicated queue monitoring interface.

Display:
- Message ID
- Campaign
- Recipient
- Selected SMTP
- Queue status
- Attempts
- Scheduled time
- Last error

Queue states:
- Pending
- Processing
- Sent
- Retry
- Failed
- Cancelled

Implement a PHP CLI worker using SQLite transactions and atomic job claiming. Use scheduled cron execution for shared hosting compatibility.

Do not run long-running email operations inside ordinary browser requests.

## 15. Development Instructions

Build the project module by module.

First deliver:
1. Complete UI design system.
2. Login page.
3. Main dashboard.
4. Sidebar and navigation.
5. SMTP account management UI.
6. SQLite schema and migration system.

Then implement the backend APIs, SMTP integration, queue processing, campaign engine, analytics and security.

Do not create fake functionality or hardcoded analytics. Every operational button must have a working backend action.

Provide:
- Complete source code
- README.md
- Installation instructions
- Database initialization script
- Cron configuration
- Sample environment configuration
- Deployment instructions for Apache/cPanel

The final application should work on standard PHP hosting with SQLite and must not require Node.js at runtime.

Important: Build a compliant email communication platform for opted-in subscribers and authorized transactional notifications. Never implement spam, unsolicited bulk sending, provider-limit evasion or SMTP identity rotation to bypass restrictions.
